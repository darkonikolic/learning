# Lab 04 — Full configuration: CLAUDE.md, settings.json, hooks, agents, skills

## Cilj
Na kraju ovog laba `task-api` ima kompletnu konfiguraciju: production-grade CLAUDE.md, settings.json s permissions, pre-tool-use hook koji logira bash pozive, subagent za code review i skill za pokretanje testova.

## Preduvjeti
- Lab 01 završen: `task-api` projekat s POST /tasks
- Lab 02 završen: GET /tasks radi
- Lab 03 završen: PATCH /tasks/:id/complete radi
- Postoji CLAUDE.md (iz Lab 01, ali ga ćemo proširiti)
- Postoji `.claude/settings.json` (iz Lab 01)

## Kontekst
Do sada si imao/la minimal CLAUDE.md koji je pokriio samo stack i build komande. Ovaj lab gradi kompletnu konfiguraciju koja je production-grade: constraints koji se mogu auditirati, permissions koji štite od grešaka, hook koji bilježi sve bash aktivnosti, i agenti/skills koji enkodiraju ponavljajuće workflow-e. Ovo je konfiguracija koju bi koristio/la na pravom projektu.

## Koraci

### Korak 1 — Napiši kompletni CLAUDE.md

Zamijeni postojeći `CLAUDE.md` s ovim sadržajem (ali prilagodi ako tvoja implementacija koristi drugačije pathove):

```markdown
# task-api

## Project
Go HTTP API za upravljanje taskovima — POST /tasks, GET /tasks, PATCH /tasks/:id/complete.
In-memory storage. Bez auth. Bez baze podataka u Phase 1.

## Stack
- Language: Go 1.21+
- HTTP: stdlib net/http s http.NewServeMux()
- Storage: in-memory []Task s sync.RWMutex u tasks/store.go
- Test: stdlib testing + net/http/httptest
- External dependencies: none (stdlib only)

## Key paths
- Entry point: main.go
- Handlers: tasks/handler.go
- Store: tasks/store.go
- Specs: docs/specs/ (čitaj SPEC prije implementacije)
- Plans: docs/plans/ (plan mora postajati prije execute)
- Decisions: docs/decisions/ (ADR i drift dokumentacija)

## Constraints
- Must not add external packages (no gorilla/mux, no gin, no gorm, no uuid library)
- Must validate all input at handler boundary before calling store
- Must return application/json Content-Type on all responses including 4xx and 5xx
- Must use sync.RWMutex: RLock for reads, Lock for writes
- Must not write to .env or any secret file
- Must not run git push without explicit user instruction

## Edit discipline
- Only modify explicitly requested scope
- Do not rename symbols unless requested
- Do not reformat or optimize unrelated code
- Preserve architecture boundaries; minimize diff size
- If required changes exceed requested scope: STOP and explain why
- List touched files before changes; explain blast radius before large refactors
- Preserve public contracts unless explicitly approved

## Conventions
- Task IDs: UUID-format strings, generated by store.AddTask() — not by handler
- Error responses: {"error": "human readable message"} — single "error" key only
- HTTP status codes: 400 invalid input, 404 not found, 409 conflict, 500 internal
- Timestamps: time.Time, stored in UTC, serialized as RFC3339

## Known gotchas
- store.List() must return non-nil empty slice (make([]Task, 0)) — nil serializes to null in JSON
- Task struct is immutable after creation except for Completed bool and CompletedAt
- Store mutex must be held for full read-modify-write cycle on Complete()
- created_at is set by store.AddTask(), not by the handler

## Non-goals (nikad ne dodavati bez eksplicitne instrukcije)
- Authentication ili authorization
- Database persistence (Phase 1 je in-memory)
- Rate limiting
- External API calls
- Paginacija ili filtriranje

## Rules (load when relevant)
- spec-before-code: .claude/rules/spec-before-code.md — zahtijeva SPEC file prije implementacije
- stdlib-only: .claude/rules/stdlib-only.md — no external Go packages
```

**Uradi ovo:**
Provjeri da svaki constraint koristi "must" ili "must not" — ne "try to" ili "prefer". Svaki vague constraint je potencijalni izvor scope creep-a.

### Korak 2 — Napiši .claude/rules/ fajlove

Napravi direktorijume:

```bash
mkdir -p .claude/rules
```

Napravi `.claude/rules/spec-before-code.md`:

```markdown
---
name: spec-before-code
description: Require SPEC file before implementation for any new feature or endpoint
---

# spec-before-code

Prije pisanja implementation koda za bilo koji feature:

1. Provjeri da li docs/specs/<feature>.md postoji.
2. Ako SPEC ne postoji: napiši SPEC prvo i STANI. Ne nastavljaj s implementacijom.
3. Ako SPEC postoji: potvrdi da acceptance criteria odgovaraju onome što ćeš implementirati.
4. Ne implementiraj bez odobrenog SPEC-a na disku.

Zašto: kod napisan bez SPEC-a ne može biti verificiran prema intentu.
SPEC je contract; testovi potvrđuju ispunjenje contracta.

Primjenjuje se na: nove endpoint-e, novu business logiku, nova validation pravila.
Ne primjenjuje se na: refaktoring postojećeg ponašanja, bug fix-eve, test additions za postojeće SPEC-e.
```

Napravi `.claude/rules/stdlib-only.md`:

```markdown
---
name: stdlib-only
description: No external Go packages — stdlib only for this project
---

# stdlib-only

task-api koristi isključivo Go standard library. Ne predlažati niti dodavati external packages.

Ako stdlib rješenje postoji, uvijek ga preferiraj nad external package-om.

Zabranjeni packages: gorilla/mux, gin, chi, gorm, google/uuid, pkg/errors, i svi non-stdlib packages.

Dozvoljeni izuzetak: eksplicitna user potvrda + go.mod komentar koji objašnjava zašto je izuzetak odobren.
```

### Korak 3 — Napiši kompletni settings.json s permissions

Zamijeni `.claude/settings.json` s ovim:

```json
{
  "permissions": {
    "allow": [
      "Bash(go build ./...)",
      "Bash(go test ./...)",
      "Bash(go test -race ./...)",
      "Bash(go test -v ./...)",
      "Bash(go vet ./...)",
      "Bash(go run .)",
      "Bash(go run main.go)",
      "Bash(git status)",
      "Bash(git diff *)",
      "Bash(git log *)",
      "Bash(git add *)",
      "Bash(curl -s *)",
      "Bash(mkdir -p *)"
    ],
    "ask": [
      "Bash(git commit *)",
      "Bash(git push *)"
    ],
    "deny": [
      "Read(./.env)",
      "Read(**/.env.*)",
      "Read(**/id_rsa*)",
      "Read(**/id_ed25519*)",
      "Bash(rm -rf *)",
      "Bash(git push --force *)",
      "Bash(git reset --hard *)"
    ]
  }
}
```

**Zašto ovakva struktura:**
- `allow`: svakodnevne operacije koje ne mijenjaju remote state — Claude ih radi automatski
- `ask`: operacije koje mijenjaju git history — Claude pita za potvrdu
- `deny`: destruktivne operacije — tvrdo blokirane bez obzira na instrukcije

### Korak 4 — Dodaj pre-tool-use hook

Pre-tool-use hook se izvršava PRIJE svake Claude tool akcije. Koristimo ga za auditovanje bash poziva.

Ažuriraj `.claude/settings.json` da uključuje hooks sekciju:

```json
{
  "permissions": {
    "allow": [
      "Bash(go build ./...)",
      "Bash(go test ./...)",
      "Bash(go test -race ./...)",
      "Bash(go test -v ./...)",
      "Bash(go vet ./...)",
      "Bash(go run .)",
      "Bash(go run main.go)",
      "Bash(git status)",
      "Bash(git diff *)",
      "Bash(git log *)",
      "Bash(git add *)",
      "Bash(curl -s *)",
      "Bash(mkdir -p *)"
    ],
    "ask": [
      "Bash(git commit *)",
      "Bash(git push *)"
    ],
    "deny": [
      "Read(./.env)",
      "Read(**/.env.*)",
      "Read(**/id_rsa*)",
      "Read(**/id_ed25519*)",
      "Bash(rm -rf *)",
      "Bash(git push --force *)",
      "Bash(git reset --hard *)"
    ]
  },
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "echo \"[$(date '+%Y-%m-%d %H:%M:%S')] BASH: $CLAUDE_TOOL_INPUT\" >> .claude/audit.log"
          }
        ]
      }
    ]
  }
}
```

**Uradi ovo:**
Napravi `.claude/audit.log` kao prazan fajl:

```bash
touch .claude/audit.log
```

Dodaj `.claude/audit.log` u `.gitignore`:

```bash
echo ".claude/audit.log" >> .gitignore
```

### Korak 5 — Napiši code-reviewer subagent

Subagent je zasebni Claude agent s ograničenim permissionsima. Ovaj agent SAMO čita kod i komentariše — nema write permissions.

```bash
mkdir -p .claude/agents
```

Napravi `.claude/agents/code-reviewer.md`:

```markdown
---
name: code-reviewer
description: Read-only code review agent. Reviews handler.go and store.go for correctness and spec compliance. Does NOT write or edit files.
model: claude-sonnet-4-6
---

# Code Reviewer Agent

## Role
Ti si read-only code reviewer za task-api projekat.
Čitaš kod i daješ preporuke. NIKADA ne pišeš niti editovaš fajlove.

## Allowed tools
- Read (čitanje fajlova)
- Bash (samo: go vet ./..., go test ./...)

## Forbidden tools
- Write
- Edit
- Bash (sve osim go vet i go test)

## Review checklist

Kada reviewuješ, provjeri:

### Handler review (tasks/handler.go)
- [ ] Svi input-i su validirani na handler boundary PRIJE poziva store
- [ ] Svaki error case vraća aplikacijski/json Content-Type
- [ ] Error responses koriste format: {"error": "message"} — samo "error" key
- [ ] HTTP status kodovi: 400 za invalid input, 404 za not found, 409 za conflict, 500 za internal
- [ ] Handler ne direktno pristupa store fajlovima — koristi store interface metode

### Store review (tasks/store.go)
- [ ] sync.RWMutex se koristi: RLock za čitanje, Lock za pisanje
- [ ] store.List() vraća non-nil empty slice (ne nil — nil serializes to null)
- [ ] Task ID-evi su generirani u store-u, ne u handleru
- [ ] created_at je setovan u store.AddTask(), ne od strane handlera

### General
- [ ] Nema external packages u imports
- [ ] Nema hardcodiranih vrijednosti (portovi, ID-evi)

## Output format

Nakon review-a, napiši:

```markdown
# Code Review: [datum]

## Handler (tasks/handler.go)
[PASS/FAIL za svaki checklist item s kratkim komentarom]

## Store (tasks/store.go)  
[PASS/FAIL za svaki checklist item s kratkim komentarom]

## Recommendations
[Sortirane po prioritetu: HIGH, MEDIUM, LOW]
```

Nemoj predlagati dodavanje external packages ili behavior koji nije u SPEC-u.
```

### Korak 6 — Napiši run-tests skill

Skill je reusable workflow koji se poziva s `/run-tests`:

```bash
mkdir -p .claude/skills/run-tests
```

Napravi `.claude/skills/run-tests/SKILL.md`:

```markdown
---
name: run-tests
description: Run all tests for task-api and report results. Use when asked to run tests, check test status, or verify implementation.
disable-model-invocation: false
allowed-tools: Bash, Read
---

## Context setup

!`go test ./... -v 2>&1 | tail -30`
!`go build ./... 2>&1`

## Instructions

Kada je skill pozvan:

1. Provjeri da li build prolazi: go build ./...
   - Ako FAIL: report build error i stani. Ne pokreći testove dok build ne prolazi.

2. Pokreni testove: go test ./... -v
   Prikaži:
   - Ukupan broj testova
   - PASS/FAIL za svaki test
   - Coverage ako dostupan

3. Pokreni race detector: go test -race ./...
   Prikaži rezultat.

4. Pokreni vet: go vet ./...
   Prikaži sve findings.

5. Summary:
   - BUILD: PASS/FAIL
   - TESTS: X/Y passed
   - RACE: PASS/FAIL  
   - VET: PASS/FAIL (broj findings)

Ako bilo što FAIL: nabroji specifičnu grešku s file:line referencom.
Ne predlažaj fix-eve u ovom skill-u — samo reportiraj rezultate.
```

## Šta si naučio

- **CLAUDE.md je project brain**: "must/must not" constraints su binarne provjere, ne guidelines — Claude ili poštuje ili ne
- **settings.json allow/deny** su tvrdi blokovi koji ne mogu biti zaobiđeni chat instrukcijama — za razliku od CLAUDE.md-a koji Claude može "zaboraviti"
- **Hooks** izvršava Claude Code harness, ne Claude model — zato je `pre-tool-use` hook koji logira siguran čak i kad je Claude distracted
- **Subagents s ograničenim permissionsima** su sigurniji od jednog agenta s punim pristupom — code-reviewer koji nema write permissions ne može slučajno promijeniti fajlove
- **Skills** enkodiraju ponavljajuće workflow-e jednom umjesto da ih kucaš svake sesije

# Lab: configure the task-api workspace

Complete workspace configuration for task-api. By the end of this lab the project has a fully configured `.claude/` directory, working permissions, two active rules, and a connected MCP server.

**Prerequisites:** task-api directory exists with at least `go.mod` and a `main.go`. Git initialized.

---


## Step 3: Write stdlib-only.md

Create `task-api/.claude/rules/stdlib-only.md`:

```markdown
---
name: stdlib-only
description: No external Go packages — stdlib only for task-api
---

# stdlib-only

task-api uses Go standard library only. Do not suggest or add external packages.

Always prefer a stdlib solution over an external package.

Packages to refuse: gorilla/mux, gin, chi, echo, gorm, google/uuid, pkg/errors.

Allowed exception: explicit user approval required. User must type "I approve adding <package>". The go.mod comment explaining the exception must be written before adding the import.

Why: stdlib-only eliminates dependency management overhead and is a deliberate learning constraint for this project.
```

## Step 4: Write spec-before-code.md

Create `task-api/.claude/rules/spec-before-code.md`:

```markdown
---
name: spec-before-code
description: Require SPEC file on disk before writing implementation for any new feature or endpoint
---

# spec-before-code

Before writing implementation code for any new feature:

1. Check whether docs/specs/<feature>.md exists.
2. If no SPEC exists: write the SPEC first and stop. Do not proceed to implementation until SPEC is confirmed.
3. If a SPEC exists: confirm the acceptance criteria cover what you're implementing.

Do not implement without an approved SPEC on disk.

Why: code without a SPEC cannot be verified against intent. The SPEC is the contract; tests confirm fulfillment.

Applies to: new endpoints, new business logic, new validation rules.
Does not apply to: refactoring, bug fixes, adding tests for already-specced behavior.
```

## Step 5: Update CLAUDE.md to reference both rules

Open CLAUDE.md. Add or update the Rules section:

```markdown
## Rules (load when relevant)
- spec-before-code: require docs/specs/<feature>.md before any implementation — see .claude/rules/spec-before-code.md
- stdlib-only: no external Go packages permitted — see .claude/rules/stdlib-only.md
```

Full updated CLAUDE.md for reference:
```markdown
# task-api

## Project
Go HTTP API for task management — POST /tasks, GET /tasks, PATCH /tasks/:id/complete.
In-memory storage. No auth. No database.

## Stack
- Language: Go 1.22
- HTTP: stdlib net/http with http.NewServeMux()
- Storage: in-memory with sync.RWMutex
- Test: stdlib testing + net/http/httptest
- External dependencies: none (stdlib only)

## Key paths
- Entry point: main.go
- Handlers: internal/handler/task.go
- Store: internal/store/store.go
- Specs: docs/specs/

## Constraints
- Must not add external packages.
- Must validate input at handler boundary.
- Error responses: {"error": "message"}, always application/json.

## Conventions
- Task IDs: generated by store, not handler.
- HTTP status codes: 400 bad input, 404 not found, 201 created, 200 success.

## Known gotchas
- Store mutex: RLock for reads, Lock for writes — not just any mutex.
- created_at is set by store.AddTask(), not the caller.

## Rules (load when relevant)
- spec-before-code: require SPEC before implementation — .claude/rules/spec-before-code.md
- stdlib-only: no external packages — .claude/rules/stdlib-only.md
```

## Step 7: Test spec-before-code rule

Open Claude Code in the task-api directory. Send this message:

```
Implement GET /tasks. Return all tasks as JSON.
```

No SPEC reference. No docs/specs/get-tasks.md exists.

**Expected behavior:** Claude checks for the SPEC, finds none, writes `docs/specs/get-tasks.md` first, and stops before implementing.

If Claude implements without a SPEC: the rule is not loading. Explicitly invoke it:
```
Check the spec-before-code rule in .claude/rules/spec-before-code.md before proceeding.
```

If that works but the rule isn't auto-loading: verify CLAUDE.md has the rules section pointing to the file. Verify the file is at `.claude/rules/spec-before-code.md` (not `rules/spec-before-code.md`).

## Step 8: Test stdlib-only rule

## Common issues

| Problem | Cause | Fix |
|---------|-------|-----|
| Rule not triggering | File in wrong path | Check: `.claude/rules/<name>.md` (not `.claude/<name>.md`) |
| Permission prompt still showing | Rule in allow but wrong glob | Test the exact command, adjust pattern |
| Claude using external package despite rule | Rule file not loaded | Add explicit reference in message: "Apply stdlib-only rule" |
| `.mcp.json` server not showing in /mcp | Session not restarted | Close and reopen Claude Code |
| settings.json ignored | JSON syntax error | Validate with `python3 -m json.tool` |

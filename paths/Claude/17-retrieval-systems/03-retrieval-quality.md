# Retrieval quality

**Theme:** Satisfaction is **not** “I got an answer.” It is “**I fetched the grounding that matches this problem slice**”—then proved it fits.

Dominant defect classes rehearse ruthlessly:

| Failure | Symptoms |
|---------|----------|
| **Wrong document** | Tangential module spec surfaces—convinced wording wrong context |
| **Stale knowledge** | Architecture pivot not re-indexed; optimistic guidance dangerously dated |
| **Wrong ownership framing** | Context blurs aggregate boundaries—invariants silently violated downstream |

Practice motifs:

Go **retry ownership** vs transport vs business idempotency—each doc class must reconcile without mixing vocabulary collisions.  

Symfony **CQRS ownership** delineations—commands vs projections vs integrations each demand distinct headings in retrieval routing.

Mandatory lab metric: annotate **minimum three QUALITY risks** per retrieval iteration before trusting synthesis—risk types may overlap staleness synonyms with chunk boundary leakage.

Discuss **semantic vs lexical** divergence: synonyms retrieve irrelevant hotspots; lexical filters rescue or mis-prune aggressively—hybrid strategy justification belongs in Retrieval Template field.

**Knowledge ownership**: named maintainers tagging SPEC revisions reduce orphan drift—surfaced at retrieval filtering time as metadata—not only narrative memory.

# Recovery + fallback

**Theme:** Choreographed multiplicity fails—design **repair loops** anticipating QA rejection, speculative architecture misstep, flaky tool modality.

Representative perturbation classes:

QA surfaces blocking defect class requiring Architect refactor partial revisit—not merely Implement tweak  

Architect narrative contradicted validated runtime behaviour forcing re-baselining requirements capture  

Integrated **tool timeouts** starving routing graph mid-handoff ambiguously orphaned

Operational recovery macro-pattern:

```
 failure classification (which hop / artefact degraded)
           → FALLBACK modality selection (narrow retry? partial degrade? escalate human?)
                             → deliberate REPAIR choreography re-enter pipeline stage cleanly
                                                     → CONTINUE under revised invariants acknowledgement
```

Fallback inventory brainstorm:

Idempotent replay of intermediate artefact regeneration  

Rolling back partially applied infra states honestly  

Introducing **human escalation** sentinel when autonomy ceiling reached ethically

Mandatory lab cruelty: ethically engineer failure seeds—simulate poisoned Planner assumptions, fractured context bridging, MCP tool starvation—observe whether detection and classification hold before drifting into blind repetitive patching.

Discuss metrics: escalating **repair iteration counts** shortening over refinements signalling maturing orchestration—not shame metric alone.

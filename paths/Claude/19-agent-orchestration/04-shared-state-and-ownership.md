# Shared state + ownership

**Theme:** Coordinating cognition without collapsing into inconsistent parallel realities demands explicit **mutable vs read-only artefacts** charters.

Pain narrative stylised:

**Agent A** adjusts an architecture diagram locally → **Agent B** builds a divergent module believing a different authority—repair thrash ensues.

Practice dimensions:

**PROJECT CONTEXT** dossier governance (living ADR appendix? pinned snapshot per epic?)  

**RULES / policy artefacts** versioning discipline  

Structured **SPEC / knowledge lattice** mutated only through enumerated roles?

Ownership matrix rehearsals (lab deliverable scaffold):

Symfony domain slice—who may alter bounded context glossary authoritative entries vs suggest pending PR commentary only.

Go concurrency module—dual ownership boundaries between infra vs application retry doctrine truth.

Operational cluster config—Terraform state mutation authority vs manifest suggestion lanes.

Articulate simultaneous **READ** clearance vs **WRITE** privilege vs **APPROVAL** escalation—three distinct axes resisting collapsed verbiage.

Shared state tooling thoughts (conceptual—not vendor prescription): ticketing ids anchoring artefacts, deterministic file locations, ephemeral scratch buffers sanitised between runs.

# Retrieval thinking

**Theme:** Ask “**what facts must enter working memory next**”—not vaguely “what do I recall.”

Operational chain:

```
 problem class identified
       → enumerated KNOWLEDGE_NEEDED bullets
           → RETRIEVAL_PLAN modality per bullet (filesystem path, MCP class, authoritative external doc tier)
                → ingestion + summarization checkpoints
                     → trimmed working overlay before implementation chatter thickens
```

Practice motifs:

Symfony **CQRS boundaries** clarified by SPEC + bounded context glossary—not guessed from legacy handler names alone.  

Go **retry ownership** validated against language runtime docs plus internal concurrency policy artefacts.

Mandatory lab habit: BEFORE dense implementation instructions, standalone mini-section **Knowledge needed** enumerated—defer coding fantasy until minimally satisfied OR explicitly flagged as unknown-unknown risk.

Discuss **ownership**: who authoritative for each datum class (platform team vs subsystem maintainers)—prevents polluted semantic memory.

- [ ] External doc pulls prefer **pinned versions / release boundaries** aligning with deployments under discussion.

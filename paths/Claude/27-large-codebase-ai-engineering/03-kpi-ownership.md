# KPI ownership

**Theme:** Without **KPIs**, optimisation is mood. Name owners and refresh rhythms.

### Starter KPI bundles (adapt targets)

**Claude / platform**

Median **iterations** to merge-ready proposal  

**Repair count** spikes per sprint  

Estimated **hallucination / grounding misses** caught in QA  

**Retrieval precision** proxy (manual spot audits or graded sets)  

**SPEC drift events** reconciled vs ignored

**Ops**

**MTTR** buckets  

Rollback execution duration / success rate  

Incident recurrence frequency tied to causal fixes

**Go**

Latency percentiles aligned to SLO  

CPU/memory envelopes on critical paths  

Queue pressure metrics correlated with concurrency experiments

**Symfony / backend modularity**

Coupling hotspots count / trend  

Structural complexity heuristic  

**Ownership leak** discoveries (boundary violations flagged in review)

**Frontend**

Bundle / interaction latency where impacting conversion or ops cost—not vanity only.

### LAB artefact

Create `ENGINEERING_KPI_BOARD` artefact—even a Markdown table—with **metric**, **definition**, **owner**, **frequency**, **current baseline**.

Connect KPI motion to Principal Template pillars where helpful.
